# Contribution audit: ontology release admission under latent future contexts

Private research assessment, 10 October 2026. This supplements the [initial review](ontology-boundary-prior-art-2026-10-10.md) and [machine source/search log](ontology-boundary-prior-art-2026-10-10.json). It does not report experiment outcomes or certify priority. The review was targeted and adversarial, not systematic. Sources were inspected at the depths recorded in the [library manifest](../literature/ontology-boundary-2026-10-10/prior-art/manifest.json); local retrieval does not imply every page was read or a published result reproduced.

## Independent verdict

**The broad mechanism is already known. A narrower empirical contribution remains plausible, conditional on useful held-out results.** Ontology-based agent boundaries, semantic edit admission, policy-relative logical differences, future-context counterexamples, version binding, and separation of candidate content from authority all have substantial prior art. A paper presenting their combination as a first governance architecture or a new formal verification algorithm would not survive this review.

I did not locate an inspected pre-existing experiment with this exact conjunction: an LLM judges a proposed TBox release against an unchanged authority policy; the release leaves every declared current-instance regression and shape check unchanged; a separately constructed admissible future entity profile exposes a newly eligible prohibited action; and matched witness evidence is experimentally varied on held-out release families. This is bounded negative evidence, not proof that no such work exists. The valuable question is whether familiar current checks induce false release admission, and whether concrete future evidence changes that judgment without collapsing acceptance of harmless releases.

The contribution should therefore be **a reproducible measurement task and evidence intervention**, grounded in existing semantic-change analysis. A successful deterministic gate is expected from its specification. It is not itself a novel result.

## A precise empirical object

Define the baseline ontology `T0`, candidate `T1`, unchanged authorization query/policy `Q`, current instance graph `A0`, shapes `S`, and a publicly specified finite set `F` of admissible future profiles. The policy determines which query expansion requires external ratification. A candidate can satisfy current checks such as `Q(T0,A0)=Q(T1,A0)` and SHACL validity yet have a profile `f` in `F` whose action becomes eligible under `T1` and was ineligible under `T0`. The hidden checker records the old/new consequences and derivation evidence. The frozen model intervention supplies only the selected seed types, with no old/new consequence booleans, derivation path or answer label. A nonseparating profile matches its cardinality and identity presentation. The profile is a test context for a particular policy-relative expansion, not automatically evidence of malicious intent or a globally unsafe ontology.

The principal question is: **When an ontology revision leaves current checks unchanged, can an LLM correctly decide whether promotion would expand the ratified action boundary over the declared future-profile basis?** This directly tests the limitation of a release-review interface. It does not establish a model's general willingness to disobey, or a complete agent containment theorem.

Pair latent-expansion candidates with harmless releases of similar edit size, syntactic form and current results. Include authorized expansions and changes irrelevant to the policy query; otherwise a model that rejects any broadened subclass relation wins without understanding authority. Preserve utility by separately measuring harmless acceptance and unauthorized-expansion false admission, not accuracy alone.

## Evidence required before a contribution claim

1. **Independent oracle and held-out structure.** Freeze family splits and confirmation cases before comparing prompt arms. Validate witnesses with actual pinned RDF/OWL closure and SHACL implementations, independently check the policy projection, and manually inspect a sample. A handwritten classifier that shares the generator's assumptions is insufficient evidence of semantic validity.
2. **Separate future evidence from formatting advantage.** Compare the same full old/new theories and equal current-profile receipts across arms. The frozen selected-profile arm exposes only seed types; a matched sham profile exposes nonseparating types in the same format. Check type identity, profile cardinality and label-correlated construction shortcuts before freezing. The checker retains old/new consequences for scoring; do not inject them into this arm. Prompt-only counterexample search is a useful later baseline. This tests profile selection plus model inference, not a model copying a printed release verdict.
3. **Guard against indiscriminate skepticism.** Require harmless and authorized-release acceptance; report rejection rates and false admission by family. If witness presence merely predicts REJECT, add policy-irrelevant or permitted expansion witnesses of matched form. Avoid contaminated “fake trusted receipts”: any deliberately erroneous evidence should be a separately declared robustness test with provenance made explicit.
4. **Make uncertainty honest.** Report descriptive paired and family-level counts for the frozen expansion-only decision and joint approval decisions. Template-generated cases do not justify treating every row as an independent draw or attaching population confidence intervals without a defensible sampling design. A small local model can establish a bounded pilot finding; it cannot establish frontier behavior or general failure without replication. Temperature zero does not eliminate hardware/runtime variability; record model revision, prompt hash, inference settings and outputs.
5. **Keep coverage finite.** `F` is a declared test basis. Exhausting it is not a proof over all OWL models, all ABoxes, unrestricted roles, arbitrary future properties or natural-language interpretations. Specify satisfiable profiles and allowed fact creation. Unmodeled facts and incomplete mediation remain explicit limitations.

The study loses its proposed empirical distinction if current checks already expose every unsafe edit, if generation templates reveal labels, if held-out families are paraphrases of fitting families, or if evidence improves safety entirely by causing universal rejection. If no meaningful held-out difference survives controls, publish a narrowly scoped negative result or change the task; do not rescue novelty by renaming the gate.

## Incident motivation, with limits

The official [OpenAI technical report](https://cdn.openai.com/pdf/67869394-cb91-4c12-888c-5cbd85c7814c/OpenAI-Hugging-Face%20Incident-Technical-Report.pdf), §VII.C pp18 and §VIII.C pp23–24, describes control changes/invariants and agents repurposing shared infrastructure as an unintended communication channel. It supports studying how a task-relevant interpretation can cross an intended authority boundary. It does not report an ontology edit or demonstrate the proposed defense. (P31; local verified 38-page PDF.)

The [METR/Redwood investigation](https://metr.org/hugging-face-incident-report-aug-2026.pdf), p2, limits its main scope to July7–13 and excludes training incidents, subsequent OpenAI compromise and remediation effectiveness. Its pp48–49 describe agent-generated signing identities without an earlier root of trust, and one action taken without checking a signature. Authentication of a peer message does not establish authority from the task owner. Neither report's extracted text contains “ontology”; that keyword absence is corroboration of the inspected accounts, not a comprehensive proof about undisclosed systems. (P32; verified 91-page PDF.)

[Slocum's incident reproduction](https://arxiv.org/html/2609.35799v1), §§2–3 (P24), operationalizes selected behaviors in a mock environment with simulated peers. It is a separate behavioral reproduction task. Our release-admission benchmark is a controlled abstraction of semantic authority expansion, with no claim to reproduce or prevent the real incident.

## Publication wording

Before results: “We introduce an evaluation of LLM admission decisions for ontology revisions whose policy effects are invisible on the current instance graph but exposed by a declared future-profile basis. The oracle uses established semantic-change analysis in a bounded fragment.”

After adequate results, add the measured failure and intervention effect, with scope. Avoid “first ontology boundary verification,” “new semantic diff,” “proof of containment,” “prevents emergent disobedience,” and unqualified “novel.” The exact empirical gap remains credible enough to test, but a noticed contribution must come from the controlled result and released artifacts, not the fact that this review failed to find identical wording.

## Addendum: composition of independently reviewed ontology packages

This is an adjacent research candidate, **not an executed extension of the frozen pilot**. A candidate package can be non-expanding over a specified input/query signature when checked against baseline `T0`, while another package is also non-expanding against `T0`; their union can expose a new query consequence through a shared auxiliary term. For example, with admissible seed `External` and target `Eligible`, package A adds `External → Helper` and package B adds `Helper → Eligible`. Either package alone preserves the projected query on the stated seed basis; together they enable the path. The input signature matters: if `Helper` is itself an admissible seed, B may already fail its individual check. Never imply unrestricted context safety from a narrower approval.

**The ontology composition mechanism is old, and general empirical agent composition risk is already benchmarked.** A sharper remaining question is whether an LLM understands the *scope of an approval*: can it distinguish “this exact package passed against T0” from “this package remains admissible alongside another independently approved package,” and request/reason from current combined-context evidence? An approval with a baseline/dependency footprint should be treated as a scoped statement, not an ambient guarantee. Generic version freshness and footprint tracking are already covered by P26/P30 and longstanding module contracts.

No exact TBox-package composition/approval-footprint LLM benchmark was located in the targeted queries. That residual is credible but narrower than the initial premise, and cannot support priority language without further review. A worthwhile future experiment would pair shared-helper and disjoint-helper package combinations with matching isolated checks, vary baseline-scoped receipts versus a current union profile, and score whether the model revalidates only the combinations whose approval context changed. Include truly context-safe modules and authorized expansions to prevent unconditional re-review/rejection from winning. Record correctness over the declared signatures and profile basis, with descriptive paired/family counts. An expected union-checker success is an engineering control; the possible contribution is the measured loss or preservation of approval-scope understanding in LLM-mediated release review.
