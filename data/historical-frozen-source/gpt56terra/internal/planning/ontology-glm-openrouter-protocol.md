# GLM 5.3 Flash hosted ontology benchmark

Evaluate `z-ai/glm-5.3-flash` through OpenRouter, pinned to the Z.AI `z-ai/fp8` endpoint with provider fallbacks disabled. The catalog identifies the model as `z-ai/glm-5.3-flash-20260826`. Hosted weights and implementation are not independently pinned or attested.

Use the existing 24 selected Gemma development tasks for technical checks and the same 192 final paired Gemma tasks for cross-model replication: 176 achievable single-edit missions and sixteen impossible controls. This is a reused benchmark, not a new held-out corpus. No configuration selection will use test answers. Freeze the source, dataset, transport requests and settings before development inference.

The baseline receives the original direct messages and one attempt. The assisted workflow receives the selected V1 computed goal states, short explanation instructions and execution feedback, with at most three attempts. Each replacement applies to the original ontology. Stop on goals met, explicit abstention or the attempt limit. No reference edit, task family or expected outcome is supplied to the model. No search, candidate enumeration, grammar or automatic output repair is used. Only the final content field is parsed; reasoning fields never supply proposals or approval.

OpenRouter reports mandatory native reasoning for this model. Request low effort and temperature zero, with a 4096-token combined reasoning/output allowance for both arms. This changes the operating point relative to Gemma's native thinking off and 96/384 caps. Hosted chat messages replace Gemma's local template and unfinished assistant prefix. Preserve raw API requests and responses, finish reasons, token usage including reasoning details, cost and generation identifiers. No seed parameter is sent because the pinned endpoint does not advertise it. Temperature zero does not guarantee deterministic hosted inference.

Run at most four concurrent independent cases, keeping a case's attempts sequential. Response caching is disabled. A response saved with its request hash can be reused on process resumption without another API call. Preserve transient HTTP failure receipts; retry 429/502/503/504 at most twice, with unchanged requests. Authentication/payment failures and ambiguous network timeouts stop the run instead of being scored as model failures. Preserve successful response receipts before local evaluation. Impose a five-dollar reported-usage ceiling, reserving a conservative estimated cost for outstanding calls; this is an operational bound, not a guarantee about unreported failed-request charges.

Primary utility is all goals met over 176 achievable test cases. Report abstention on the sixteen impossible controls separately, success by attempt, per-family errors, parse failures, length finishes, calls, input/output/reasoning tokens and API-reported dollars. Compare baseline and assisted on matched cases; keep development and smoke/setup results separate. Gemma comparisons describe different model/backend/format/reasoning/budget configurations, not a causal model-size comparison.

Use unchanged complete permission review, independent edit application and materialization, all nine simulated approval modes, immutable commit replays, and supplemental OWL RL/SHACL checks of final applicable candidates. Hash exact requests and responses. The API does not return independently verified native token IDs, so API token counts are provider reports rather than reconstructed tokenizer inventories. Approvals remain hypothetical trusted registry inputs; no deployed tool action or real ontology release occurs.
